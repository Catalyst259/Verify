# 业务规则
首先明确用户流程，由于该应用目标为携程小程序，因此不单独设计鉴权机制，用户通过携程小程序的鉴权机制登录后，直接使用携程小程序的用户信息进行操作。用户上传材料后，系统会对材料进行分析，提取出与目标地点相关的主张（CLAIM），并对这些主张进行分类和验证。最终，系统会根据用户上传的材料和提取出的主张，为用户提供个性化的旅行建议和路线规划。
业务流程如下：
```markdown
1. 用户通过携程小程序登录，系统获取用户信息；
2. 用户进入小程序主页，用户输入 TARGET_PLACE + MATERIAL；
3. 对 MATERIAL 做 Normalization，确保模型得到正常的输入
4. 模型解析 MATERIAL，提取与 TARGET_PLACE 相关的 Claim；
5. 后台对 CLAIM 进行分类，并根据 CLAIM 类型调用不同的检索代理进行证据检索；
6. 系统对检索到的证据进行验证，判断其真实性和可靠性；
7. 检索完成，每个代理生成结构化的检索报告；
8. 系统将检索报告进行整合，由最终整合 Agent 对每个检索结果进行整合与评估；
9. 根据调研结果输出最终的旅行建议和路线规划，提供给用户。
```
以下为需要严格遵循的业务规则与Code约束，按业务流程梳理

## 材料形式(MATERIAL)
目前的计划是用户上传一个目标地点（TARGET_PLACE）和一个MATERIAL，材料可以是文字、图片或 LINK，材料中可能包含与目标地点相关的主张（CLAIM）。
MATERIAL 枚举如下：
```python
enum MATERIAL:
    TEXT = 1
    IMAGE = 2
    LINK = 3
```
目前支持的材料形式为：
1. 文字类材料：包括但不限于网页、文章、新闻、博客、论坛、社交媒体、评论等；
2. 图片类材料：包括但不限于截图、照片、图片等；
3. 链接类材料：包括但不限于网页链接、社交媒体链接、视频链接等。

## 目标地点(TARGET_PLACE)
用户在提交 MATERIAL 时，必须同时输入一个明确、完整的目标地点名称。

例如：
- ✅ 上海迪士尼乐园
- ✅ 武康大楼
- ✅ 上海海昌海洋公园
- ❌ 迪士尼
- ❌ 那个海边
- ❌ 上海一个很火的公园

限制：
1. TARGET_PLACE != null
2. TARGET_PLACE.trim() != ""
3. TARGET_PLACE.length() >= 1 && TARGET_PLACE.length() <= 100

## 主张枚举(CLAIM)
拿到用户上传的材料与旅行地点，第一步是要分析用户上传的文字、图片与链接内容，提取出与旅行地点相关的主张（CLAIM），并对这些主张进行分类和验证。CLAIM 为如下枚举。当前实现允许没有明确主张时返回空列表，主图直接结束为 `no_claims`；提取阶段不通过搜索补造主张。地点只用于限定范围，前端要求至少提供一种待核验材料。仅地点 HTTP 请求仍保留 `no_claims` 返回。
CLAIMTYPE 枚举如下：
```python
enum CLAIMTYPE:
    FACT = 1
    ROUTE = 2
    CROWD = 3
    EXPERIENCE = 4

class Context:
    def __init__(self, claim_type: CLAIMTYPE, content: str):
        self.claim_type = claim_type
        self.content = content

class Claim:
    def __init__(self, claim_type: CLAIMTYPE, content: str):
        self.claim_type = claim_type
        self.content = content
```
1. FACT：事实类主张，通常存在明确的事实状态，例如“免费、开放、需要预约、允许宠物”等。
2. ROUTE：路线类主张，通常存在明确的路线状态，例如“地铁步行 5 分钟、机场 10 分钟”等。
3. CROWD：人群类主张，通常需要结合星期、节假日、时间段、季节等条件，例如“周末人少、不排队”等。
4. EXPERIENCE：体验类主张，不判断简单真假，而分析体验是否一致，例如“安静、隔音好、适合看日落”等。
