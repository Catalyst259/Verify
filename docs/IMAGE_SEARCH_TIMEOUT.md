# 图片核验超时修复

## 触发与原因

图片提取出多条主张后，多个类别子图会共享浏览器并发槽位。原实现的外层使用
240 秒运行预算，内部却依据 300 秒子图配置，安排约 295 秒的工作和约 265 秒的
搜索阶段。真实故障中，一条主张等待槽位约 148 秒；外层先取消子图，结果被
`TimeoutError: 子图超过运行预算 240 秒` 覆盖，已经完成的主张和取到的材料一并丢失。

另外，外层使用预算总量而非提取后的剩余量；等待信号量也在搜索超时范围之外，
即使内部取证预算耗尽，排队任务仍可能阻止 Validate 与结果汇总。

## 修复行为

- 外层根据运行的绝对截止时间计算剩余量，不延长预算，不在并行分支中修改共享截止时间。
- 类别子图根据相同的剩余量设置内部截止时间，继续预留清理、结果汇总和 Validate 时间。
- 等待浏览器槽位与实际搜索纳入同一个有界 Search 阶段，预算耗尽后不再启动排队的浏览器任务。
- 各条主张分别记录排队或取证超时；已收集材料继续进入 Validate，已完成结果不会被整批覆盖。
- 超时仍作为技术失败显示，不把执行失败改写成成功或普通的证据不足。

默认 240 秒预算、浏览器并发数和来源访问限制均未扩大。

取证取消后的浏览器清理也受内部绝对截止时间约束，而非始终另花最多三秒。
图片提取耗尽大部分预算时，清理时间会随剩余量缩短；内部 Validate 可能诚实报告超时，
但已登记的材料仍可在主图硬截止前组装，不会因第二次取消被替换为空结果。

用户真实复测又发现：取证已经有效 `done` 后，关闭浏览器被 Search 截止时间取消，
会覆盖成功返回并误报“取证超时”。现在在关闭前校验、保存完成结果；仅清理阶段失败
时保留有效取证，并单独保留清理诊断。真正没有完成的搜索、排队超时及硬取消仍记为失败。
正常用完工具额度返回的真实记录也按同一规则处理。
关闭任务在内部绝对截止时间及最多三秒的双重约束内，可以使用原本为收尾预留的时间；
Search 首次取消会等待这一有界关闭，然后继续传播取消。主图硬截止再次取消仍可中止，
不增加总预算，也不扫描或停止用户的其他浏览器。

小红书每次查询仍验证当前搜索页、候选和登录/访问状态；同一次核验中再次命中的笔记
正文可以复用首次真实读取记录，保留原抓取时间，仍经过每条主张的工具额度、输入排除
和去重校验。缓存只存规范化正文，不存签名链接；每次核验重新创建，不跨请求复用。
原有四秒访问间隔、结果上限和专用 profile 锁保持不变。

一次批量来源读取最多使用 Search 截止前的时间，额外预留最多十秒给来源清理及 Agent
下一次决策/结束；部分来源材料和错误继续如实返回。Agent 任务和工具回包包含实时
`remaining_budget.time_seconds`，排队后剩余很短时可以及时结束，避免再启动整批取证。

真实复测中，超时修复保留了已取得的材料，但又暴露了 Fact Validate 返回无效 JSON
的问题。DeepSeek 的 Plan/Validate 现使用 JSON mode，把业务数组装在唯一的 `items`
字段内传输，随后解包为原有数组交给节点校验。空数组合法，额外字段、错误结构和
截断响应仍拒绝，不增加自动重试或延长预算。其他兼容模型保持原数组协议。
传输格式依据 [DeepSeek JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)；
原有主张范围、证据引用和判定一致性校验继续执行。

## 回归覆盖

`tests/test_verification_deadlines.py` 覆盖：

1. 真实图片上传、SQLite 恢复图片原始 bytes、提取来源引用、主图与类别子图完整链路；
   一条主张正常完成，另一条已取证后超时，返回部分结果并保留双方证据。
2. 通过真实 Chrome 前端上传图片并提交同样的场景，检查结果展示和未完成项。
3. 所有浏览器槽位被占用时，排队任务及时结束，不启动浏览器，Validate 仍能完成。
4. 已消耗大部分预算时，外层只等待剩余时间，截止时间不会被延长。
5. 共享预算已过期时，不再调用模型或搜索。

这些回归使用模型与取证替身压缩故障时长，不验证公网可用性或模型判断质量。
旧版图片浏览器测试还沿用了其他类别尚未实现时的状态断言；现已按照四类子图
均可执行、且本测试模型选择跳过的实际契约更新，保留图片顺序、多模态输入和页面读取检查。
测试读取中文提示词文件时显式指定 UTF-8，避免 Windows 默认 GBK 解码失败。
`tests/test_category_model_json.py` 另覆盖 DeepSeek 请求参数、数组解包、空结果、
截断与无效结构拒绝，以及真实类别图的 Plan/Validate 传输和后续校验。
超时回归还调用真实 `run_search` 编排并替换浏览器与 Agent 为内存替身，覆盖共享预算
只剩不足一秒、清理本身耗时的取消场景，确认材料保留、槽位释放且没有外层空失败。
新增完成记录回归还验证有效 done/正常用完额度不会因清理取消变成 Search 失败；
`tests/test_xiaohongshu_run_cache.py` 覆盖运行内正文复用、并发命中、跨运行隔离、原始
时间和新证据 ID、访问限制及错误笔记身份拒绝。来源批量耗时回归验证截止前交还
部分正文，留下实际结束决策时间，而不把来源超时伪装成来源完整成功。

运行：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_verification_deadlines.py -q
$env:VERIFY_BROWSER_TESTS = '1'
# 如使用系统 Chrome，设置 VERIFY_CHROMIUM 为实际可执行文件路径。
.\.venv\Scripts\python.exe -m pytest -q
```

公网限流、登录失效、不可访问页面或模型返回无效 JSON 仍会如实报告。一次慢搜索能够
保留部分结果，不代表材料已得到充分证据支持。原始故障日志和本机复测记录保存在
工作区的 `handoff/image-timeout-fix-20261008/`，不随公开仓库发布。
