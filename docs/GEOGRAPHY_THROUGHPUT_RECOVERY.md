# 地点范围与多主张取证修复

2026-10-09，测试副本。

## 地图地点范围

完全同名的地点不能仅凭名称相同就当作用户的目标。解析器通过供应商的行政实体确认城市范围，再检查 POI 的城市、国家及供应商提供的范围坐标。路线的裸起终点继承提交的目标地点范围；明确具有其他城市范围的端点仍可用于真实跨城路线。

行政范围无法确认、供应商失败或返回歧义时，保留未知坐标和证据不足，不根据候选排名猜测。接口的 `place_resolver(str)` 仍兼容，自带解析器新增内部 `resolve_scoped` 能力，标准路线会话调用它；自定义解析器继续使用原调用方式。地图服务的距离限制保持原值。

请求限流在单调时钟上循环核对等待时间，并从上一请求完成后计算下一次间隔，避免计时器提前唤醒、客户端初始化或传输延迟缩短实际请求间隔。等待仍消耗原运行预算。

主图初次解析目标地点也受原运行截止时间约束，包含等待全局地图锁的时间。耗尽预算时取消解析，保留已提取主张和未知地点，后续类别明确报告运行预算失败；不重新累计时间或构造坐标。解析器自身在预算结束前抛出的异常不被误当成这个截止时间。

城市前缀识别支持有限的中文前缀及英文形式，不是完整的多语言地名消歧。地名中含其他城市名的道路等实体可能保守地返回未知；用户提供明确城市有助于定位。未知坐标不被伪装成有效地图证据。

## 多主张取证

此前积压时按主张数平分时间，常把导航、读取、模型结束压缩成约十秒；同时小红书仍先收集十个候选，取消后销毁整个浏览器，造成连续冷启动和失败。

现在小红书按本批实际正文配额收集候选，提前排除本 Claim 前轮、本轮已读笔记及输入原帖。正常操作取消仅在安全关闭查询页后保留已登录上下文；启动、访问限制及清理异常仍重置资源。登录、验证码、速率和正文完整性检测继续执行。

导航完成不等于页面应用就绪。首页搜索控件和对应关键词页面使用有界、持续检查登录与访问限制的等待，候选只在网站、路径及关键词完全匹配后读取。永久异地跳转或错误关键词仍拒绝；安全诊断只记录路径类别和匹配布尔值，不记录原始地址、关键词或签名参数。

用户确认同一登录窗口的手动搜索正常，隔离探针证实新版首页隐藏了旧输入框。搜索现通过实际可见的旧输入框或新版搜索区及其获得焦点的输入组件提交，保留网页自身的导航事件。新版 `/search_result_ai` 对关键词额外编码一次，只有恰好一个关键词、一次解码后与请求完全一致才允许读取笔记卡片；旧 `/search_result` 保持原来的精确匹配。AI 回答不入账，实际笔记正文仍由独立详情页和笔记 ID 检查获得。没有强行操作隐藏控件、构造站点签名或调用私有接口。

明确的 `/website-login/captcha` 路径视为访问限制，即使页面上残留推荐卡片也停止采集。登录失效或访问限制在本次运行内共享，等待中的其他主张直接获得相同的受控错误，避免反复重启浏览器；下一次运行重新检测。已取得的真实材料保留，后续主张不继承前一条的材料或引用。

提取结束后，主图按完整输入批次预判积压，在各类别开始异步计划前生效，避免先结束计划的类别独占浏览器。独立调用类别图也按完整批次预判；这是保守调度，不替模型选择或丢弃主张，地图槽位独立。

共享预算的每批网页 Search 先取一份实际正文，由 Validate 决定是否需要下一批补搜。小输入也使用这项配额，避免只有两条主张时预读十篇占满整轮；没有共享预算的独立调用保留原默认策略。积压运行的单条窗口最多三十秒，始终受原来的绝对截止时间约束，后续等待者也保持同样的服务策略。第一份实际正文登记后即可结束本批 Search，不再额外扣除用于下一次模型调用的读取时间。程序返回真实账本及全部工具错误；候选卡片或模型摘要不算正文。判定仍检查相关性、充分性和独立性，不以取证完成代替主张可信。

配置小红书且首批正文配额为一份时，以现有 Plan 的目标结合用户地点直接调用既有来源取证与工具登记路径；取得有效正文后返回本批完整账本，不再启动仅为备用网页候选而创建的浏览器或 Search Agent。它仍是原小红书来源，不另建爬虫。未取得正文、来源失败或查询过长时保留原 Agent/网页流程，并使用原剩余截止时间、已用工具预算和已有错误；超长查询不截断，实际错误不清除。其他配额与独立网页工具仍保留原并行来源行为。

这个查询用于取得首批材料，不表示已回答具体问题；Validate 对完整主张判定相关性、充分性和缺口，必要时补搜。实际小红书正文配额在校验通过且截止前完成登记时立即捕获完成账本，后续收尾不能把已完成取证变成失败；所有后来记录的工具错误仍保留。普通网页正文登记不触发这个提前完成快照，原有 Agent 完成与技术超时边界保留。

同一次请求的同一主张可能被多个类别选择。它们可复用已经实际取得的正文，原材料仍只保存在本次来源包装器的已有正文缓存中；类别各自通过原工具登记新的证据编号，保留原始抓取时间，不把缓存读取伪记为新搜索或第二份独立来源。别名只从成功取证的实际笔记产生；不同主张、不同请求、输入原帖及当前类别已读的旧轮材料不命中。缓存命中仍执行原查询/配额/截止时间校验，资料锁内检查关闭和访问限制，并保留有界取消。

专用小红书会话串行执行；原来两个 Claim 同时准入后，后者仍在来源内部排队，消耗了自己的三十秒服务窗口。配置该来源时，Service 将共享网页准入容量设为一个；直接调用类别图的局部预算同样匹配，其他网页来源默认两个、地图两个不变。排队仍消耗原绝对运行截止时间，服务窗口在公平队列准入后计算。不同 HTTP 请求仍共用资料锁，不能将本次队列修复解释成跨请求同时访问同一个 profile。

详情导航保留配置的最小访问间隔，以来源所有者的单调时钟计算；搜索与页面加载已经消耗的时间计入间隔，只等待尚未满足的部分。正文搜索和输入长链/短链共用该规则，导航失败或取消也记录实际结束时刻；等待取消不记为发出请求，浏览器重置和下一次运行不清空间隔。没有降低配置值、修改验证码判定或引入新的爬虫。

可选补搜只有在共享预算可容纳下一波服务和模型收尾时启动，否则明确保留本轮判定、材料和未解决问题。首次真实失败不会清除。整轮默认240秒、输入排除和证据引用守卫保持。

三十秒窗口不能保证任意数量的主张都完成，小红书 profile 仍串行使用；外部网络或人机验证也可能造成部分失败。改进来自减少浪费与及时释放资源，不是对平台可用性的保证。

## 判定纠正

首次 Validate 即向模型提供每条活动主张可引用的实际证据 ID 清单，以及三个引用数组的本轮枚举 Schema，内部任务和 HTTP 响应字段不变。枚举用于指导生成，程序仍独立严格检查归属。未知引用、模型格式及类别规则错误都进入同一次有界纠正，反馈包含被拒绝的完整判定、原因和允许的引用。模型响应不完整或不是有效 JSON 时，使用原材料重新生成，绝不采用残缺响应的片段；重生成和语义纠正共用一次机会。此前人流判定引用发布时间未知的材料会直接失败，没有获得已有的纠正机会。

纠正仍校验场景、时效、测量数值、主张范围和引用归属；不替换 ID 或猜测日期，不能用发布时间未知的材料支持人流结论。有效的其他判定不重做，真实取证错误不会被纠正清除。第二次模型返回仍无效或超过原截止时间则明确失败。模型可能不遵守提示中的枚举，不能以一次成功保证后续均成功；实际错误和负面验收记录留存。
