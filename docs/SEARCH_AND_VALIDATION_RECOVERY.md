# 取证调度与判定恢复

一次输入提取出较多主张时，原实现会让前两条浏览器取证长期占用槽位；小红书专用资料锁又将批量正文读取串行化，后来类别可能始终没有入场机会。模型的错误引用和单条判定格式错误，还可能使整批有效结果一起丢失。本轮分别修复调度、路线适用范围与逐条判定恢复；外站限制和预算耗尽仍保留为可见未完成项。

## 取证预算

- 每次请求建立一个 `RunBudget`，总预算仍为 240 秒。链接读取、提取、地点解析、排队、模型纠正和取证都使用原绝对截止时间，不因入场或重试重新计时。
- 所有网页类别共享两个浏览器槽位。dispatcher 先取得实际槽位，再按类别轮换选择等待主张，使较晚到达的类别获得后续服务机会。排队超时和取消会移除等待项并返还许可；空队列不会留下调度任务。
- 取得槽位后才分配主张服务切片。存在积压时，按剩余 Search 时间、并发数及待完成数计算，最多 30 秒；只剩一两条任务时保留原阶段截止时间。该规则不会抢占已经运行的任务，也不能预知尚未入队的类别。
- 使用切片时，从切片中给清理预留至多 3 秒。剩余取证时间至少 20 秒时，小红书每次查询最多登记两篇正文，否则最多一篇；无积压时保留原来源配置。来源查询再留出至多 10 秒、最多四分之一剩余时间，供 Agent 查看材料并结束。
- 小红书仍使用单一共享资料锁、登录及访问限制检测和原访问节流。已读取正文可在同一次请求中复用，但每条主张单独登记证据 ID，输入原笔记仍排除在独立证据之外。
- 地图 HTTP 使用独立的两个槽位，不占浏览器槽位；仍受同一次运行的截止时间约束。诊断增加类别字段，区分同一主张在不同子图中的取证记录。

## 路线适用范围

ROUTE 测量原文中明确的通行耗时。计费单位如「150 元/小时」、排队、营业、参观和游玩时长不进入地图时长比对；仅有景点顺序或距离时也不由模型补出时长。识别以句段为边界，避免把相邻价格或等候描述的时长移给行程。

地图只提供实测依据；判定仍须保留原目标、交通方式、主张秒数和容差，并引用该主张实际取得的测量。价格等被排除的内容仍可由其他适合的子图按内容选择。

地点来源不再直接采用排名第一的有限坐标。候选须与完整实体名称或服务返回的别名一致；查询附带的行政限定须由候选行政地址确认。没有确认的端点沿原路径返回 `UNVERIFIED`，并保留无法解析的说明，不把其他实体的坐标当作本次行程。

候选校验不限制国家或地区，不猜城市或坐标。完全同名的跨地域实体仍可能有歧义：例如服务将“杭州西湖”精确同名匹配到高雄住宅，名称一致性本身不足以确认杭州范围。该限制没有因流程完成而消失，后续定位验收须给出明确行政城市和具体实体。

## 计划输出恢复

供应商返回不完整响应、无效 JSON 或错误传输对象时，模型适配器抛出专用 `ModelOutputError`。Plan 可在原截止时间内重新请求一次完整输出；不拼接、补括号或采用被拒响应中的片段。重新生成和原有字段纠正共享一次机会，最多两次模型调用。网络、鉴权和普通运行异常不触发该补救。

首次规划仍按类别选择活动主张；补搜必须覆盖原活动主张并保持已有范围。每次输出都继续经过原 Schema、主张 ID 和范围校验，第二次仍错时明确失败，不追加第三次请求。

## 判定恢复

- 先验证输出结构与主张 ID，再逐条执行本类别 Schema，隔离格式错误、缺失结果和错误引用；有效条目保留。
- 模型明确返回 `evidence_sufficient=false`，却同时给出确定结论或置信度时，向保守方向收束为 `UNVERIFIED`、`confidence=null`，并记录规范化说明。原范围、引用、实测及其他字段仍须通过完整校验；不借此补齐非法或缺失字段。
- 只对需要纠正的条目追加一次调用，反馈字段错误及该条主张允许引用的证据 ID。纠正仍使用原截止时间；不能引用其他主张、示例编号或输入来源充当独立证据。
- 再次无效或超时仍拒绝该结论。已登记材料、其他有效判定、补搜前的有效结果及真实 Search 错误保留。没有材料时生成空引用的 `UNVERIFIED`，不调用模型制造依据。

`POST /api/verifications` 的请求字段和成功响应结构保持不变。执行状态 `completed` 只表示该流程完成，不表示主张成立；`UNVERIFIED` 表示尚无足够依据。
