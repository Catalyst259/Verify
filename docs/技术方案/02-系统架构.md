# 系统架构

[返回总览](README.md) · [核验规则](03-数据采集与核验规则.md)

## 运行结构

一个仓库、模块化单体，API 与后台 worker 分进程运行，共用 PostgreSQL。

```text
移动 H5
  └─ HTTPS / SSE → FastAPI → PostgreSQL（任务、证据、结果、事件）
                                  ↕
                           Worker / LangGraph
                                  │
           输入提取 → 地点确认 → Claim 分类 → 并发取证
                                  │
                 FACT 官方信息 / ROUTE 地图 / CROWD 评价
                                  │
              去重 → 场景匹配 → 支持与反证 → 充分性检查
                                  │
                  必要时补查 → 逐条结论 → 旅行行动
```

前端包含输入页、确认与进度页、结果页和证据弹层。结果按“结论→理由→证据”展开，先呈现最影响决策的主张，完成一条显示一条；部分失败可单独重试。

## 模块分工

| 模块 | 输入 → 输出 | 负责的工作 |
|---|---|---|
| InputUnderstanding | 图片/链接/文字 → 地点候选、原始主张、原文位置 | 视觉/OCR、输入解析、主张拆分 |
| PlaceContext | 候选与用户条件 → 已确认场景或待确认项 | POI、城市、入口、日期、时段、时区 |
| EvidenceAcquisition | Claim + 场景 + 预算 → 证据与缺口 | 类型路由、搜索、抓取、地图、反证、去重 |
| ClaimVerification | Claim + 证据 + 规则 → 结论与引用 | 时间适用性、场景匹配、冲突和充分性判断 |
| ReportProjection | 已完成结果 → 卡片、总结、后续行动 | 排序、展示、替代地点；不生成额外事实 |

模型负责提取、语义关联和解释；代码负责单位换算、日期逻辑、引用校验、调用预算、缓存失效和允许输出的结论。实时数据、历史快照和测试样本使用可替换的数据适配器；携程内部接口待取得权限后接入。

## 核心数据

业务表：`runs`、`inputs`、`claims`、`evidence_documents`、`claim_evidence_links`、`verdicts`、`events`、`jobs`。checkpoint 使用框架专用表。

| 对象 | 关键内容 | 必须保持的规则 |
|---|---|---|
| Run | 会话、POI/入口、出行日期/时段、时区、`context_version`、截止时间 | 场景修改产生新版本，旧结果不能混入 |
| Claim | 原文、类型、谓词、范围、限定词、原文位置 | “免费且免预约”拆开；保留“所有/通常/约”等含义 |
| Evidence | 来源 URL、发布者、原文摘录、hash、抓取/发布/到访/有效时间、来源模式 | 不同时间分开；未知为 null；搜索摘要不当原文 |
| ClaimEvidenceLink | 支持/反对关系、匹配场景、独立来源组、排除原因 | 立场属于“证据与主张的关系”，不属于整篇文档 |
| Verdict | 标签、理由、成立条件、证据 IDs、反证记录、限制、规则/模型版本 | 引用可解析；证据不足需说明缺口 |
| Event / Job | 事件序号、租约、attempt、上下文版本 | 可恢复、结果幂等提交，过期任务不能覆盖新结果 |

来源模式区分 `live_fetch / archived_snapshot / user_supplied / synthetic_fixture`。宣传截图属于待核验材料，不能作为独立支持证据。

任务状态与事实结论分开：任务可以处理中、待确认、部分完成或失败；工具超时不能直接让主张变成“错误”。

## 最小接口

| 接口 | 行为 |
|---|---|
| `POST /api/runs` | 提交输入，返回任务 ID；支持幂等键 |
| `POST /api/runs/{id}/context` | 确认或修改场景，更新版本并重算受影响项 |
| `GET /api/runs/{id}` | 获取当前版本完整快照 |
| `GET /api/runs/{id}/events` | SSE 推送已落库事件，携带序号和场景版本 |
| `POST /api/runs/{id}/claims/{claim_id}/retry` | 单条重试，保留历史 attempt |
| `GET /api/runs/{id}/evidence/{evidence_id}` | 获取原文摘录、时间、场景及支持/反对关系 |

## 恢复与一致性

- worker 通过数据库任务表和租约领取任务；扩展多 worker 时使用原子领取。按任务、场景版本、Claim 和 attempt 去重提交，旧租约不能覆盖新 attempt。
- 使用持久化 checkpoint。业务结果与事件在同一事务提交，再推送 SSE；进程重启后可以恢复，外部请求可能重复，但结果提交幂等。
- SSE 断线按事件序号补读，或获取完整快照；反向代理关闭流式缓冲。
- 地点、入口或日期修改后，取消或废弃旧版本，迟到响应不得更新当前卡片。
- 缓存键包含 POI、入口、日期/时段、交通方式和供应商；高变化运营信息优先刷新。

初始预算：最多 5 条 Claim、同时处理 3 条、最多两轮检索、最多 12 次外部搜索、整体截止 120 秒。重试消耗同一预算，超时保留已完成结果。这些参数需实测调整。

## 输入与数据保护

只抓取 HTTP(S) 公网地址，每次跳转都检查目标，拒绝私网和云元数据地址；限制文件大小、类型、跳转和下载时长。网页与 OCR 中的指令只当数据，工具参数由后端校验；引用片段可定位，HTML 清理后展示。

任务和证据按会话隔离，文件使用受限持久卷，日志屏蔽密钥、签名链接及无关个人信息。浏览器采集不携带用户登录态。

## 后续演进

取得携程权限后，将 POI、票种/房型、产品状态和履约后评价接入统一证据结构，先解决 POI 映射、作用范围、到访日期与刷新周期。数据量和并发增长后，再增加对象存储、独立采集队列、横向 worker 或向量检索。
