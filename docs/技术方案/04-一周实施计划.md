# 一周实施计划与验收

[返回总览](README.md)

按 2–3 人、一周规划；团队人数未确认。前端负责交互，后端负责核验与任务，数据/集成负责来源、地图和评测。下列指标为开发目标，尚未实测。

## 每日交付

| 日期 | 重点 | 当日成果 |
|---|---|---|
| Day 1 | 选试点 POI，确认模型/搜索/地图资源，试取真实数据 | 一个 FACT 从输入到原文引用；冻结基本数据结构 |
| Day 2 | 上传、地点确认、结果卡、证据弹层；任务落库与事件流 | 截图→Claim→FACT 完整链路，界面展示真实状态 |
| Day 3 | 接入高德 POI/路线、入口确认和场景版本 | FACT + ROUTE 可用，修改入口后正确重算 |
| Day 4 | 公开评价、到访场景、去重、反证和充分性 | 三类主张同屏，包含反证和证据不足案例 |
| Day 5 | 替代地点、真实页面跳转、恢复、幂等、超时与成本记录 | 完整 Demo；首轮质量、延迟和费用结果 |
| Day 6 | 用户试用、人工检索对照、关键错误修复、部署演练 | 核心验收用例通过，冻结主要流程 |
| Day 7 | 复查变化信息、额度与联网依赖，走台和录屏 | 实时主链路与明确标注的快照回放备用 |

首日优先排查公开评价覆盖和 API 可达性。若只有一人，缩小到 3–5 个 POI、一个搜索供应商、一种官网解析器，减少地图装饰和动画，保留三类核验流程、反证、场景对齐和出处。

## 验收方案

准备 12 份截图/文本、约 36–48 条 Claim，三类尽量均衡；按 POI 和来源切分开发集、保留集，人工标注场景、证据和结论。覆盖错误入口、同名地点、部分收费、过期通知、节假日、转载、日期不明、来源失败。

| 项目 | 建议门槛 |
|---|---|
| 提取与路由 | 记录提取 precision/recall 与漏项；类型路由正确率目标 ≥90% |
| 引用 | 验收集 100% 能定位原文；引文支持对应理由及场景的比例目标 ≥95% |
| 严重误判 | 固定对抗用例中，错误场景被当有效证据、直接反证被判支持的次数为 0 |
| 反证与不足 | 每条有反证检查；所有预设缺证据用例正确保留不足 |
| 决策价值 | 与同模型、近似搜索预算的普通联网问答比较；至少 3 名试用者交叉进行人工查找对照 |
| 性能与成本 | 记录总耗时、确认场景后的处理耗时、p50/p95、调用数和单次费用 |

另比较关闭反证、关闭场景过滤后的结果，验证两项设计的实际价值。小样本只报告样本内表现，不宣称整体产品准确率。

必须通过的工程行为：改日期/入口后旧结果失效；来源失败不影响已完成项且可单条重试；worker 重启恢复且结果不重复提交；SSE 断线恢复；转载不重复计票；异常 URL、网页指令和非法引用不会污染结果；历史/合成数据不标成实时。

## 延迟与预算

目标：首张结果卡 ≤25 秒，完整报告 45–90 秒，整体截止 120 秒。冷启动、热缓存和来源失败分别计量，用户确认时间单独记录。

| 费用项 | 预算依据 |
|---|---|
| 搜索 | Tavily 在 2026-09-29 的文档价格：basic 1 credit、advanced 2 credits，按量 US$0.008/credit；每次 8 次搜索约 US$0.064 / US$0.128，仅搜索项 |
| 模型 | 按实际模型、地域、输入/输出与视觉 Token 计费，记录 usage；重试和思考 Token 计入 |
| 网页提取与地图 | 按账号实际配额计费，不能默认永久免费 |
| 部署 | 优先现有主机；云主机可预留 ¥100–300 短期预算，此项为估算；首周无需 GPU |

单次总费用 = 模型 + 搜索 + 提取/浏览器 + 地图 + 存储/主机摊销。免费搜索额度还会被调试和提取消耗，不作为完整开发预算保证。[Tavily 定价](https://docs.tavily.com/documentation/api-credits) · [百炼定价](https://help.aliyun.com/zh/model-studio/model-pricing)

## 演示顺序

1. 上传含 3–5 条卖点的截图，确认地点、入口和出行日期。
2. 展示“免费但部分区域收费”，展开原文与成立条件。
3. 用实际地图响应解释路线是否符合宣传。
4. 展示客流支持/反对样本，说明工作日反馈为何不能证明周末情况；证据不足时保留不足。
5. 按原始需求给出有依据的替代地点，跳转真实 POI/产品页面。

没有正式交易深链时使用有效公开页面；没有地图权限时明确路线只演示流程。实时检索与历史快照分开标识。

开工前需要确定：团队人数、预算与部署地区、三类 API 账户、首批城市/POI，以及比赛官方评分和提交要求。
