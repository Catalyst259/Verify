# 竞品借鉴与技术选型

[返回总览](README.md)

## 竞品结论

旅行产品提供输入与业务衔接参考；事实核验系统提供主张拆解与取证参考。商业产品未公开的内部技术栈，不作为选型依据。

| 产品 | 值得借鉴 | 与本项目的区别 |
|---|---|---|
| [TripGenie](https://www.trip.com/newsroom/tripgenie-new-features-2/) | AI 结果衔接行程、协作与预订 | 侧重旅行规划；所引公开材料为 2024 年功能介绍 |
| [圆周旅迹](https://r.app.xiaomi.com/details?id=com.chaochaoshishi.slytherin) | 链接、图片、文字导入后提取地点 | 侧重行程整理；依据已有商店资料 |
| [Mindtrip](https://mindtrip.ai/) | 截图/PDF 导入、地图、评论和旅行操作 | 导入识别已成熟，产品差异应放在核验 |
| [Perplexity Search](https://docs.perplexity.ai/docs/search/quickstart) | 来源展示、域名过滤、搜索结果 | 搜索结果仍需回到原文，不能直接充当核验结论 |
| [Google Fact Check Tools](https://developers.google.com/fact-check/tools/api/reference/rest/v1alpha1/claims/search) | 主张与核验记录一一对应 | 检索已有核验，不自动裁决任意旅游主张 |
| [Full Fact AI](https://fullfact.org/ai/) | 值得核验的主张识别、重复检测 | 面向专业核验团队，仍依赖专家 |

## 开源实现结论

| 项目 | 公开栈 / 机制 | 采用的思路 |
|---|---|---|
| [DEFAME](https://github.com/multimodal-ai-lab/DEFAME) | 多模态、动态核验流程、搜索工具、Firecrawl/BeautifulSoup | 最接近本题；借鉴工具和核验逻辑的拆分，补充旅行场景规则 |
| [SAFE](https://github.com/google-deepmind/long-form-factuality) | Python、原子事实、搜索增强核验 | 拆成可检验主张，限制补查轮数；“未获支持”不等于错误 |
| [WikiChat](https://github.com/stanford-oval/WikiChat) | Python、FastAPI、Chainlit、Qdrant、Docling | 提取、检索、检查分开；首周不复建其维基索引 |
| [GPT Researcher](https://github.com/assafelovic/gpt-researcher) | Python、FastAPI、LangChain/LangGraph、并行搜集 | 借鉴采集与并发；不采用多网站重复信息多数票裁决 |
| [Vane，原 Perplexica](https://github.com/ItzCrazyKns/Vane) | Next.js、React、TypeScript、SQLite、SearxNG | 全 TS 搜索应用参考，仍需自建类型路由和场景核验 |
| [Dify](https://github.com/langgenius/dify) | 可视化工作流、工具集成、RAG | 提示词试验或备选编排层，复杂证据逻辑仍需代码 |
| [AVeriTeC](https://github.com/MichSchli/AVeriTeC) | 主张、证据问题/答案、裁决与解释 | 评测证据是否回答核验问题，不能代替中文旅行评测集 |

采用组合：**DEFAME 的工具拆分 + SAFE 的原子主张 + WikiChat 的可替换检索**，实现小型领域流程，不直接整体 fork 通用研究系统。

## 推荐技术栈

| 层级 | 选择 | 理由 |
|---|---|---|
| 前端 | React + TypeScript + Vite | 适合移动 H5 和宿主嵌入，无需额外 SSR 服务 |
| 后端 | Python 3.12 + FastAPI + Pydantic v2 | 采集、抽取和评测生态成熟，便于结构化校验 |
| 编排 | LangGraph + 持久化 checkpoint | 支持地点确认暂停、逐条并发、有限补查和恢复 |
| 存储 | PostgreSQL + JSONB；SQLAlchemy/Alembic | 一套数据库管理任务、证据、结论和迁移 |
| 模型 | 百炼视觉模型 + 文本模型 | 先测 `qwen-vl-plus` / `qwen-plus` 非思考模式；用旅行样本确定并冻结版本 |
| 搜索 | 首接 Tavily，Perplexity Search 作备选 | 先验证中文有效来源命中率和部署地区可达性 |
| 采集 | httpx + Trafilatura/BeautifulSoup；必要时 Playwright | 静态正文优先，浏览器只服务明确需要渲染的站点 |
| 地图 | 高德 POI / 步行路线 API | 取得地点、入口及实际路线依据 |
| 部署 | Docker Compose + 文件持久卷 | 首周部署简单；后续按需要迁移对象存储 |

模型组合是起测选择，尚无本项目效果排名；JSON 格式能力也不能替代业务校验。

## 备选与延后项

| 方案 | 结论 |
|---|---|
| 全 TypeScript | 团队明显偏 JS 时可采用，保留同样的数据模型和核验规则 |
| asyncio 显式状态机 | LangGraph 接入成本过高时可替代，但仍需持久化与失效控制 |
| Dify 主编排 | 团队难以维护代码流程时考虑；避免同时维护两套流程定义 |
| 向量数据库 | 首周先按 POI、日期、来源过滤，再做关键词/BM25；有评测收益后再加向量检索 |
| 微服务、Redis、Kafka、Kubernetes | 首周不引入；按队列压力和运维需求再扩展 |
| 自由规划的多 Agent | 首周采用明确步骤与调用上限，保证可解释、可恢复 |

复用代码时注意：Dify 有附加许可条件；Firecrawl 核心为 AGPL、部分 SDK 许可不同；AVeriTeC 标示非商业许可；GPT Researcher 根 LICENSE 与包元数据存在差异，应按实际文件和版本核对。具体依据见[原文](../验一下-技术栈与架构调研.md)。
