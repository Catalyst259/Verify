# 数据采集与核验规则

[返回总览](README.md) · [系统架构](02-系统架构.md)

## 数据接入

| 数据 | 首周来源与方式 | 关键限制 |
|---|---|---|
| 开放、票价、预约、施工 | 官方网站、政府/运营方公告，白名单定向采集 | 官方旧文也可能失效，必须看适用时间与范围 |
| POI、入口、路线 | 高德 POI 和步行路线 API | 入口字段不一定完整，需要确认；路线是估计值 |
| 客流与排队体验 | 搜索发现可访问的公开评价/游客叙述，再取得正文 | 需要到访日期和时段；样本有偏差，不等于实时客流 |
| 携程内部数据 | 后续正式接口接入 | 当前不能将公开采集或样本标作内部数据 |

采集默认用 httpx + Trafilatura/BeautifulSoup，必要时针对指定站点用 Playwright；图片公告/PDF 再用视觉/OCR，保留原图与位置。搜索只用于发现候选，最终引用回到原文。

每个站点记录来源归属、允许路径、解析器、刷新频率、更新时间提取方式和最近成功状态。检查正文是否包含目标内容，HTTP 200 不代表取得有效证据。遇到登录墙、验证码或限流时，使用其他公开来源或授权接口，保留不可用原因。

首周提前准备少量有出处的真实快照用于回放，并与实时联网、用户材料、合成测试样本明确区分。公开评价的可用性是最大数据风险，应在第一天验证。

## 三类主张的裁决

### FACT：事实与运营状态

优先使用目标地点当前官方信息，同时查闭园、收费区域、预约、施工和节假日特别安排。

- “免费”必须分清大门、展馆、活动和停车；部分免费输出具体成立条件。
- 没有售票库存不能推导闭园；今天抓到的网页不能自动视为今天有效。
- 直接、当前、适用的公告可以单独构成充分证据，无需凑来源数量。

例如，[上海植物园票务页面](https://www.shbg.org/sites/zhiwuyuan/InfoList.aspx?ctgId=70cd8e24-7067-475a-9898-f6964c3d98d1)区分“免大门票”和“售票专类园另购”。这一范围信息不能扩展为所有日期、所有项目免费。

### ROUTE：交通方式、出入口与实际路线

确认具体地铁出口和景区可开放入口，使用同一坐标系调用高德 `GET /v5/direction/walking`，按需要设置 `show_fields=cost`，保存原响应中的米/秒及查询时间。[接口文档](https://lbs.amap.com/api/webservice/guide/api/newroute)

- 不用站点中心到景区中心的直线距离替代步行路线。
- 出口不明确时比较合理候选；只有特定出口满足，就输出条件；入口未知则保留不足。
- “约 5 分钟”与略有差异的估计值不机械判冲突，容差政策需要样本标定。
- 地图估计不包含排队、安检或个体步速；路线反证主要是实际入口、绕行与封闭信息。

### CROWD：到访场景与样本范围

同时查找支持“人少”和反对“人少”的内容，按同一地点/入口、真实到访日期、时段、季节筛选。可从近 30–60 天开始检索，再按季节和来源覆盖调整。

- 区分普通周末、法定节假日和调休工作日；星期字段本身不够。
- 发表日期不等于到访日期；无法确认到访场景的评价不能直接支持“周末人少”。
- 一条可靠反例可推翻“所有周末都不排队”，不能单凭它否定“通常人少”。
- 输出样本时间范围、独立来源数量和限制，不生成总体拥挤概率或未来客流承诺。
- 订单/热度即使来自内部接口，也只是代理信号，不能直接等同入园人数。

没有足够评价时，保留 CROWD 卡并说明缺少什么证据，不用泛化评论填补结论。

## 所有类型共用的规则

1. **主张拆分**：每条一个可检验谓词，保留“所有、通常、大约”等限定词；宣传截图不是独立支持证据。
2. **场景优先**：先检查 POI/入口、范围和适用日期，再判断内容是否支持主张；抓取、发布、到访、有效时间分别保存。
3. **去重与独立性**：按 URL、正文 hash、近重复文本和明确共同引用去重；三站转载同一公告只算一个信息来源；独立性未知就保留未知。
4. **主动反证**：每条有反证检索或结构化检查记录；同时保留支持信息，不能只挑负面内容。
5. **充分即停**：证据直接回答主张且适用时停止；存在缺口则有限补查；冲突无法消解或预算耗尽时输出不足。
6. **引用约束**：每个理由关联具体原文片段；总结仅引用已完成结果，不新增事实。

## 输出标签

| 结论 | 使用条件 |
|---|---|
| 当前证据支持 | 有适用、直接且充分的支持证据 |
| 仅在特定条件下成立 | 条件下存在足够支持，并明确说明条件 |
| 与当前高质量证据冲突 | 有适用的直接或高质量反证 |
| 原描述可能已过期 | 有状态变更依据或明确失效时间；日期未知不等于过期 |
| 当前证据不足 | 缺关键场景、来源不可用或冲突尚未解决，说明具体缺口 |

CROWD 使用上述标签时必须限定样本范围。EXPERIENCE 后续单独采用“体验一致/分化/依赖场景”等表达；MARKETING 未定义客观指标时暂不核验。

结论展示原始说法、标签、一句话理由、适用场景和更新时间；展开后查看支持/反对原文及来源。关键卖点不成立时，再按用户原始需求推荐替代地点，未核验的属性明确标注；推荐因素不能改变核验结论。
