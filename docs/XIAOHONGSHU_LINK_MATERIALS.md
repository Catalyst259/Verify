# 小红书链接图文核验

用户在原有链接框粘贴小红书笔记 URL 或分享文案，填写地点后点击开始评估。仅链接输入及与文字、上传图片混合提交均走现有提取、四类核验和结果展示。

## 数据流

1. 前端提取分享文案中的 HTTP(S) URL，去除外围标点并按输入顺序去重；前后端独立校验笔记长链及 xhslink.com 短链。拒绝用户主页、搜索列表、其他域名、用户信息和异常端口。
2. VerificationService 为请求建立一次 RunBudget，使用本次运行的小红书来源包装器逐条调用 read_note。登录浏览器仍由应用级 XiaohongshuSource 持有，输入读取与取证搜索共用同一资料锁。
3. 输入导航手动接管文档 HTTP 跳转：每次请求禁止自动跟随重定向，只把已校验的站内目标转为下一次文档导航。最终页面必须是笔记，长链跳转后须保持原笔记 ID。保留访问参数，但日志中的链接查询参数被脱敏。
4. 页面正文稳定后，按 DOM 的轮播序号切换全部配图，等待图片加载并截取图片元素；截图时隐藏轮播控件。重复轮播克隆、头像、表情、评论和推荐图不计入。空正文但有配图可处理。视频及包含视频的材料明确报不支持。
5. LinkMaterial 在 runtime context 中携带原始 URL、规范 URL、标题、正文和内存 PNG；不写进上传数据库或 LangGraph State。提取 Agent 接收准备好的材料并禁止网页导航。正文与配图的 source_type 均为 LINK，source_ref 为原始 URL。
6. 同一请求内按笔记 ID 缓存输入材料，短链别名解析后复用，重复提交的同一 URL 直接复用；不跨请求缓存，也不放进独立取证正文缓存。原始 URL 与解析后的规范 URL 均加入 input_urls，沿用现有笔记排除规则。

材料来源由后端身份校验决定：如果模型把本次确已读取配图的笔记 URL 标成 IMAGE，统一纠正为 LINK。只对精确匹配且实际含配图的输入 URL 进行此纠正；未知 URL、未提交图片及没有配图的链接仍拒绝。真实模型曾出现这种误分类，不能仅依赖提示词保证来源类型正确。

## 超时与失败

锁等待、跳转、正文和图片读取、模型提取消耗同一个运行截止时间；来源同时受现有 xiaohongshu.timeout_seconds 限制。错误响应说明第几条链接或第几张图失败，保留原始失败性质；不会把不完整读取标为成功。取消向上传播，页面和浏览器清理有上限。既有取证预算、正文缓存和完成结果保留逻辑不变。

第三方 Agent 会记录任务字符串，因此应用安装日志记录脱敏器，删除小红书 URL 的查询参数。模型输入和返回给提交者的来源 URL 保持原值；API Key、Cookie 和原始签名链接不放进交接日志。

## 测试与维护

`tests/test_link_materials.py` 验证 URL 契约、原始来源、短链解析后的排除、失败状态和共享截止时间；`tests/test_link_reader_browser.py` 使用系统 Chrome 与合成页面验证逐跳拦截、轮播顺序、懒加载、纯图片、登录/验证、失效笔记、图片失败、取消及输入缓存。已有 API、文字图片混合提交、DeepSeek 多模态和原有超时回归一并保留。

本机测试日志、真实公开笔记验收结果、启动进程和提交号保存在工作区上级 `handoff/xiaohongshu-link-20261008/`。合成页面与模型替身只证明工程链路，不代替真实网站及模型验收；真实运行的证据不足、partial 和来源受限均须如实留档。
