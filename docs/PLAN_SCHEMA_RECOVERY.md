# 规划输出格式纠正

`Claim.type=FACT` 表示主张大类。`FactPlan.fact_type` 表示核验所需的细分类，只接受 `OPEN_STATUS`、`PRICE_POLICY`、`RESERVATION`、`ACCESS_POLICY`、`FACILITY` 和 `TEMPORARY_EVENT`。将 `FACT` 写入后者会被严格校验拒绝。

## 执行边界

- 四类子图在 Plan 收到有效 JSON 数组、但部分计划字段不符合本类别 Schema 时，最多追加一次模型纠正。
- 纠正前先校验原计划的主张 ID。非法、重复、缺失或非活动 ID 不进入纠正；补搜仍须覆盖全部活动主张。
- 仅将格式错误的计划与字段错误作为 `planning_feedback` 交给模型，已通过校验的计划由程序保留。纠正返回必须覆盖全部待纠正 ID，不能用空数组删除难以处理的计划。
- 纠正后仍执行 Schema、主张 ID 及补搜范围校验。六类事实类型保持不变，不将所有 `FACT` 直接替换为某一类别。
- 纠正使用当前 Plan 的原截止时间，不重置子图或运行预算。模型传输失败、截断响应、无效 JSON 和业务范围变更不触发该格式纠正。
- 成功的主张在结果 `notes` 中记录「计划格式纠正成功」。再次无效或超时仍返回 Plan 未完成项；补搜失败保留上一轮证据和判定。

`POST /api/verifications` 的字段及成功响应结构保持不变。Plan 格式错误属于核验执行未完成，不能将它解释为主张为假。

## 验证

回归覆盖 19 条计划中 9 个非法事实类型、有效计划保留、六类分类、四类共享骨架、供应商 JSON 包装、ID 与选择范围、纠正失败、原预算超时、补搜范围和历史保留。
