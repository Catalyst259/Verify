# 默认十条的后端实时爬虫接入方案

## 目标与回退

每次 Fact 网页搜索使用相同关键词并行调用小红书来源，默认最多读取十条笔记原正文，直接登记核验证据。旧 GUI、Excel、转换 CLI 和离线 JSONL 接入撤出当前分支。

开始执行前检查工作区、远端、最新 main 和相关进程。已将完整旧 Verify 可恢复归档到本地 `../handoff/rollback/20261006-161019/Verify`，再从 main `55c22d0e39689fb88215ce62f118195302336098` 克隆并创建 `feat/xiaohongshu-crawler`。归档保留旧提交、被忽略的数据、登录资料、配置、环境及日志，不发布归档。

原爬虫目录保留。用户新采集的十四条笔记留在归档；后端复用本次登录资料的副本，原件不改写。

## 模块与数据流

- XiaohongshuSource 兼容已有 EvidenceSource.search(query) → list[Evidence]，通过 VerificationCapabilities.evidence_sources 的 xiaohongshu 项注册，并接入 Fact 实际调用链。
- 复用原爬虫的公开 DOM 搜索、正文读取和访问限制检测，使用异步 Playwright；后端不依赖 GUI、Excel或预采集文件。
- 每次 search_web 并行执行网页候选搜索与小红书实时搜索。两来源分别登记查询计数，小红书自动读取原正文；网页候选继续通过 read_page 读取。
- 配置 xiaohongshu.max_results 默认 10，支持 1–10。固定 WEB 类型，保留标题、正文、作者、净化链接和实际读取时间，未知发布时间为 null。HTTP 四字段请求及返回模型保持兼容。
- 所有实际查询和正文读取通过 SearchSession.execute 计数、生成运行内证据 ID、去重及引用校验。在统一登记处按笔记 ID 排除本次输入，覆盖链接变体和重定向。

## 预算与浏览器生命周期

每轮最多 20 次工具调用、5 次查询，每查询最多 10 个候选、每轮最多 15 份新增证据，最多两轮。十条小红书正文与五条网页正文，加两次查询，共十七次调用；上限不保证每次采满。爬虫后续批次至少保留一次网页正文调用及一个证据槽位；剩余预算或时间不足时返回实际材料，不补造结果。

单次爬虫超时默认 120 秒，包含等待锁，且不得超过 Fact 剩余截止时间。Fact 与主图外层子图超时均默认 300 秒。并行查询分别更新自己的结果槽位。

后端持有一个异步来源实例，以锁串行访问专用登录会话，查询参数、输入排除和证据账本保持请求隔离。Windows 使用单 worker、无 reload。正常采集隐藏浏览器，单独 --login 命令打开浏览器供用户手动登录。取消、超时和后端退出均清理浏览器操作。

登录失效、验证码、限流、页面变化或超时时明确记录错误，保留有效材料并继续网页核验，不自动处理验证或回退到历史 JSONL。数量增加不直接提高可信度评分，继续按权威性、独立性、时间与交叉核对结果判断。

**本地必需验收全部通过并留档后，才允许执行 git push。**

1. 合成页面至少提供十条有效笔记，验证一次查询登记十条，随后仍能读取网页正文；配置调低、超限拒绝及实际不足十条均有检查。
2. 覆盖并行计数、共享预算、输入排除、去重、请求隔离、部分失败、登录失效、超时取消及失败后继续网页核验。
3. 后端完整测试和真实本地浏览器/API 链路通过；账号登录可用时再验证真实小红书模块，真实模型质量另行标注。
4. 复核归档和原工具保存、提交清单、源文件哈希、配置及登录资料忽略规则。
5. 保存交接、机器可读验证结果和本地启动记录，再启动新后端供用户测试。
