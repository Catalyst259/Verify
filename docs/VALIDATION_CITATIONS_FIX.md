# 无效证据引用与路线请求修复

复现：西湖游览顺序与断桥起点建议在取证失败后，Validate 引用未登记到该主张的证据，页面显示「判定引用了该 Claim 未取得的证据」。这属于执行错误，不能据此判断主张为假。

## 行为

- 四类核验没有累积证据时，由程序生成 `UNVERIFIED`、空引用、空置信度；不再调用模型判定。已有 Search 错误仍保留为未完成项，正常无结果仍可按原规则补搜。
- 有证据但本轮模型引用未取得的 ID 时，仅对对应主张纠正一次，并传入该主张允许引用的 ID。使用原截止时间；有效主张、已有材料与上轮有效判定不受影响。
- 纠正后再次出现非法引用或纠正超时，仍拒绝结论并保留错误。原有目标范围、证据归属、客流场景、体验来源与路线数值约束均保留。
- ROUTE 只为原文含明确时长的主张生成时长比对计划。仅有游览顺序、起点建议或距离的内容不生成虚构时长；事实或体验子图仍自行选择这些内容。
- Valhalla 的 GET `json` 查询改用紧凑 JSON，避免空格编码为 `+` 后服务返回 HTTP 400。真实公共坐标对比确认：原带空格请求 400，紧凑 GET 与 JSON POST 均为 200。

## 验证与交接

新增回归覆盖四类无证据、Search 失败、跨 Claim 引用、一次纠正成功/再次失败、纠正截止时间、有效结果隔离、部分取证错误保留，以及中文/英文时长与游览顺序边界。

真实地图调用、真实西湖文本核验及开发期间的负结果保存在项目根目录之外的 `../handoff/validation-citations-fix-20261008/`；恢复后的最终回归、提交号和运行清单保存在 `../handoff/validation-citations-fix-20261009/`。以最终交接记录为准。真实检索仍可能遇到平台限制或时间预算耗尽；这时必须保留未完成项，不能将其伪装成核验通过。
