# 文档更新

## Goal

让仓库文档与实现一致，未参与设计的维护者能读懂四类子图各自做什么。

## Why

`README.md` 和 `docs/成果/主图设计.md` 目前都写着「路线、客流和体验子图仍返回未实现状态」。实现完成后这些描述会变成假的，而文档是维护者的第一入口。

## Decisions

必须反映的事实：

- 四类子图的判定语义差异（真假 / 数值比对 / 场景条件 / 体验一致性）
- 公共编排骨架的存在与三个注入点
- 能力槽位（含新增 `map_routing`）的职责
- 演示阶段地图供应商的临时性与替换边界
- `CROWD` 信号源是「公开评价密度」近似而非实测客流
- 同一 CLAIM 多项发现的冲突检测

文档按 `AGENTS.md` 的注释规范写：说明业务含义、必要约束、输入输出、异常及行为原因；不写对话引用或依赖讨论上下文才能理解的表述。

## Scope

- `README.md`
- `docs/成果/主图设计.md`
- 必要时 `docs/成果/Fact子图设计.md`（骨架抽取后）

## Acceptance

- 不再有「未实现」的过期描述。
- 四类判定语义的差异被明确写出。
- 演示阶段的限制（地图供应商、客流近似）被如实记录，不夸大能力。
- 现有测试全绿（文档不破坏代码）。

## Notes

- 语言与仓库现有文档一致（中文）。
- 不要写成设计讨论记录，写成维护者可直接读的说明。
